# 一键润色建议（简历分析面板）实现思路

## 1. 背景与目标

简历分析面板（Resume Analysis）会对用户简历进行 AI 评审，产出「分数分布 / 优势 / 建议」三块内容。其中每条**建议**（suggestion）包含以下字段：

- `title`：建议标题
- `impact`：影响程度（`high` / `medium` / `low`）
- `why`：为什么这样改
- `exampleRewrite`：示例改写（可空）
- `copyPrompt`：改写指令

原面板只能「展示」建议，用户需要自己对照着手动修改简历，操作成本高、易遗漏。

本次新增**一键润色**：在每条建议内加一个魔法棒按钮，点击后把「用户简历内容 + 建议内容」一起发给 Agent，由 Agent 读取简历并应用 JSON Patch 同步更新简历；更新完成后，允许用户**二次确认**「保留更新」或「恢复原版」。

## 2. 整体数据流

```
用户点击魔法棒
   │
   ▼
前端 onPolish(suggestion)
   │  调用 orpc.agent.messages.polish({ resumeId, suggestion })
   ▼
后端 messages.polish (protectedProcedure + 限流)
   │
   ▼
agentService.messages.polish
   │  1. getOrCreateForResume 复用/创建线程
   │  2. 运行锁 + 配额检查
   │  3. buildPolishUserMessage 构造指令
   │  4. createAgent + agent.stream
   │  5. consumeStream 非流式消费 UI 消息流
   │  6. 按 startedAt 查询最新 agentAction
   ▼
返回 Action | null
   │
   ▼
前端 onSuccess(action)
   ├─ action 非空 → 展示「保留 / 恢复」二次确认区
   └─ action 为空 → 提示「该建议无需改动」
```

## 3. 后端实现

### 3.1 新增 RPC 端点 `agent.messages.polish`

文件：`packages/api/src/features/agent/messages.ts`

- 复用 `protectedProcedure` + `aiRequestRateLimit` + `mapAgentEnvironmentError`。
- **输入**：`{ resumeId, suggestion: { title, impact, why, exampleRewrite, copyPrompt } }`，经 Zod 校验。
- **输出**：`Action | null`，可空表示 Agent 判定「无需改动」。

```ts
polish: protectedProcedure
  .route({ method: "POST", path: "/agent/messages/polish", ... })
  .input(z.object({
    resumeId: z.string(),
    suggestion: z.object({
      title: z.string().trim().min(1),
      impact: z.enum(["high", "medium", "low"]),
      why: z.string().trim().min(1),
      exampleRewrite: z.string().nullable(),
      copyPrompt: z.string().trim().min(1),
    }),
  }))
  .output(z.object({ id, title, summary, status, canRollback, appliedUpdatedAt }).nullable())
  .handler(({ context, input }) =>
    agentService.messages.polish({ userId: context.user.id, ...input }))
```

### 3.2 核心服务 `agentService.messages.polish`

文件：`packages/api/src/features/agent/service.ts`

流程（与既有 `messages.send` 保持一致的结构，仅把「流式返回」换成「非流式执行 + 查询 action」）：

1. `assertAgentEnvironment()` 断言 AI 环境可用。
2. `threads.getOrCreateForResume` 复用/创建该简历对应的线程。
3. 状态校验：`archived`、`activeRunId`（已有活动运行）、`read-only`（无 `workingResumeId` / `aiProviderId`）。
4. 运行锁：`AbortController` + `activeRunControllers` + `claimActiveAgentRun`。
5. `consumeThreadMessageQuota` 扣减配额。
6. `buildPolishUserMessage` 构造用户消息并 `persistMessage`；首条消息时同步线程标题。
7. `markUsed` 标记 provider 已用。
8. `createAgent` + `agent.stream`。
9. **`consumeStream` 非流式消费** `result.toUIMessageStream(...)`：润色是同步 patch 操作，无需向用户流式展示过程，消费掉 UI 消息流即可触发 Agent 完整执行（`onFinish` 内完成 token 结算、响应消息持久化、运行清理）。
10. 按 `startedAt` 查询本次运行产生的最新 `agentAction`，返回 `toAction(action)` 或 `null`。

```ts
const startedAt = new Date();
// ... claim run / quota / persist ...

const result = await agent.stream({ messages: modelMessages, abortSignal: controller.signal });

await consumeStream({
  stream: result.toUIMessageStream({
    originalMessages: messages,
    generateMessageId: generateId,
    sendSources: true,
    onFinish: async ({ responseMessage, isAborted }) => { /* token 结算 / 持久化 / 清理 */ },
    onError: (error) => (error instanceof Error ? error.message : "Agent run failed."),
  }),
});

const [action] = await db
  .select()
  .from(schema.agentAction)
  .where(and(eq(schema.agentAction.threadId, thread.id), gte(schema.agentAction.createdAt, startedAt)))
  .orderBy(desc(schema.agentAction.createdAt))
  .limit(1);

return action ? toAction(action) : null;
```

### 3.3 提示词构造 `buildPolishUserMessage`

文件：`packages/api/src/features/agent/service.ts`

明确约束 Agent 的执行路径：先 `read_resume` 读取简历，再 `apply_resume_patch` 应用修改；同时要求**保持原有语言 / 语气 / 结构，不修改与该建议无关的内容**，避免 Agent 过度改动。

```
Polish my resume by applying the following suggestion. First read the resume with
read_resume, then apply the changes with apply_resume_patch. Keep the resume's existing
language, tone, and structure, and do not modify anything unrelated to this suggestion.

Title: <title>
Impact: <impact>
Reason: <why>
Example rewrite: <exampleRewrite>          # 可选
Instruction: <copyPrompt>
```

## 4. 前端实现

文件：`apps/web/src/routes/builder/$resumeId/-sidebar/right/sections/resume-analysis.tsx`

### 4.1 状态与 mutation

```ts
const [polishingTitle, setPolishingTitle] = useState<string | null>(null); // 正在润色的建议标题
const [polishedAction, setPolishedAction] = useState<{ id; title } | null>(null); // 已润色、待确认的 action

const { mutate: polishSuggestion } = useMutation({
  ...orpc.agent.messages.polish.mutationOptions(),
  onSuccess: (action) => {
    setPolishingTitle(null);
    if (action) {
      setPolishedAction({ id: action.id, title: action.title });
      toast.success(t`Resume polished.`);
    } else {
      toast.info(t`No changes were needed for this suggestion.`);
    }
  },
});

const { mutate: revertAction } = useMutation({
  ...orpc.agent.actions.revert.mutationOptions(),
  onSuccess: () => { setPolishedAction(null); toast.success(t`Original content restored.`); },
});
```

### 4.2 单条建议的按钮状态机

以 `suggestion.title` 作为匹配键，三条分支互斥：

1. `polishingTitle === suggestion.title` → 显示「Polishing…」禁用态（带 Spinner）。
2. `polishedAction?.title === suggestion.title` → 隐藏润色按钮，显示**二次确认区**：`Keep changes` / `Restore original`。
3. 其余 → 显示魔法棒「Polish」按钮，点击触发 `onPolish`。

`onPolish` 把建议字段映射为后端 `suggestion` 入参后调用 `polishSuggestion`；`onRestore` 调 `revertAction({ id: polishedAction.id })` 复用既有快照回滚。

## 5. 关键设计决策

1. **完全复用 Agent 既有链路**：不新增 patch 逻辑，直接复用 `getOrCreateForResume` → `createAgent` → `apply_resume_patch` 工具链，仅把输入换为「简历 + 建议」的组合指令，避免破坏原有架构。

2. **非流式 `consumeStream`**：润色是同步 patch 操作，用户无需观看流式过程，用 `consumeStream` 消费 `UIMessageStream`（`AsyncIterable & ReadableStream`）触发完整执行即可；结束后按 `startedAt` 时间窗查询最新 action，天然规避并发/历史消息干扰。

3. **恢复复用既有 `actions.revert(actionId)`**：`agentAction` 在应用 patch 前已保存整份简历快照，回滚直接走现有端点，无需新增回滚 API。

4. **输出可空**：当 Agent 判定该建议无需改动（未产生 `apply_resume_patch` action）时返回 `null`，前端给出「无需改动」提示而非报错，交互更友好。

5. **类型对齐**：`suggestion` 入参字段与 `analysisSuggestionSchema` 的 `impact` 枚举（`high | medium | low`）完全一致，前端 `ResumeAnalysis["suggestions"][number]` 可直接映射，无类型断裂。
