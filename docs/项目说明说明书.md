# Reactive Resume 项目说明说明书

> 一个开源的简历构建与分享平台：在线编辑简历 → 实时预览 → 导出 PDF/DOCX → 公开分享，并内置 AI 助手（Agent）辅助写作与优化。

---

## 1. 项目概述

| 项目 | 说明 |
|---|---|
| 名称 | Reactive Resume |
| 形态 | pnpm Monorepo（Turborepo 管理） |
| 技术栈 | React 19、TanStack Start（SSR 路由）、Vite、Hono、Node.js、oRPC、Drizzle ORM、PostgreSQL、Better Auth、React PDF、AI SDK |
| 部署形态 | 生产环境为单个 Node.js 进程（端口 3000），`apps/server` 同时承载 API / 认证 / MCP / OpenAPI / 静态资源，并回退服务 `apps/web` 构建产物 |
| 运行要求 | Node.js 24 + pnpm 11.17.0（corepack）+ Docker（PostgreSQL，可选 SeaweedFS 对象存储） |

## 3. 各功能核心实现思路

### 3.1 简历可视化编辑（Builder）

**核心实现思路：**
- **路由分层**：`apps/web/src/routes/builder/$resumeId/` 下按职责拆分：
  - `route.tsx`：路由入口，加载简历并注入上下文；
  - `index.tsx`：编辑器主页面（分为内容区与预览区）；
  - `-components/`：页面级组件（顶部工具栏、字体/字号、分页设置等）；
  - `-sidebar/`：侧边栏章节编辑器（46+ 组件，如 `basics`、`work`、`skills` 的编辑表单）；
  - `-store/`：本地状态（zustand 风格），持有当前简历数据与撤销/重做栈。
- **数据同步**：前端修改后通过 oRPC 调用 `packages/api` 的 resume 变更接口（POST/PATCH），由 `packages/resume/src/patch.ts` 提供 JSON Patch 操作辅助，按最小增量提交，支持冲突回滚。
- **预览即真实**：左侧编辑、右侧直接渲染 `packages/pdf` 的 React 组件，实现“所见即所得”。

**关联代码资源：**
- 路由与页面：`apps/web/src/routes/builder/$resumeId/*`
- 前端状态与 hook：`apps/web/src/features/resume/`（51 个文件，含编辑器逻辑、版本对比、导入）
- JSON Patch 领域逻辑：`packages/resume/src/patch.ts`
- API 变更过程：`packages/api/src/features/resume/{crud.ts,router.ts,service.ts}`
- 版本快照：`resume_version` 表（见 `packages/db/src/schema/resume.ts`）

### 3.2 多模板渲染引擎

**核心实现思路：**
- **模板注册**：模板名由 `packages/schema/src/templates.ts` 的 `templateSchema` 枚举定义（azurill/bronzor/chikorita/ditgar/ditto/gengar/glalie/kakuna/lapras/leafish/meowth/onyx/pikachu/rhyhorn/scizor），同时 `packages/schema` 提供 `Template` 类型。
- **模板实现**：`packages/pdf/src/templates/<name>/` 每个模板一个目录，内部为 React PDF 组件（Header/排版/章节渲染）；`index.ts` 汇总导出所有模板组件。
- **共享基础**：`packages/pdf/src/templates/shared/`（48 个文件）沉淀所有模板共用的章节过滤（`filtering.ts`）、通用排版原语与工具函数，模板仅保留各自的视觉差异。
- **封面/附信**：共享目录中含 cover-letter 布局，支持简历封面页。

**关联代码资源：**
- 模板枚举：`packages/schema/src/templates.ts`
- 模板组件：`packages/pdf/src/templates/<15 个模板目录>`
- 共享逻辑：`packages/pdf/src/templates/shared/filtering.ts`
- 模板汇总与测试：`packages/pdf/src/templates/index.ts`、`index.test.ts`
- 静态预览图：`apps/web/public/templates/{jpg,pdf}`

### 3.3 PDF 生成与预检

**核心实现思路：**
- **入口文档**：`packages/pdf/src/document.tsx` 的 `ResumeDocument` 根据 `data.metadata.template` 挑选模板组件并渲染完整 PDF 文档。
- **双端适配**：
  - 服务端：`packages/pdf/src/server.tsx` 用 `renderToBuffer` 渲染为 `File`（`createResumePdfFileResult`），先 `inspectResumePdf` 做语义检查；
  - 浏览器：`packages/pdf/src/browser.tsx` 走 `@react-pdf/renderer` 浏览器端生成。
- **语义检查**：`packages/pdf/src/semantic/` 提供 `inspectResumePdf`、`hasSemanticErrors`、`renderPreflightPdf`，用于预检分页是否溢出、内容是否丢失、字体是否缺失等。
- **字体注册**：`packages/pdf/src/hooks/use-register-fonts.ts` 统一注册标准 PDF 字体、CJK 回退字体栈与全局连字符规则。
- **本地化标题**：章节标题按语言解析（`section-title`），由调用方传入 `resolveSectionTitle`。

**关联代码资源：**
- 服务端生成：`packages/pdf/src/server.tsx`
- 浏览器生成：`packages/pdf/src/browser.tsx`
- 语义预检：`packages/pdf/src/semantic/{preflight-core.ts,semantic 相关}`
- 字体：`packages/pdf/src/hooks/use-register-fonts.ts`
- 导出包入口：`packages/pdf/package.json` 中 `./server`、`./browser` 导出子路径

### 3.4 数据模型与持久化

**核心实现思路：**
- **简历模型**：`packages/schema/src/resume/data.ts` 定义 `ResumeData`（Zod schema），包含 `metadata`（模板、字体、布局、主题色、分页）与各 section（`basics`、`work`、`education`、`skills`、`projects`、`awards`、`publications`、`interests`、`languages`、`custom` 等），并导出 `parseResumeData` 运行时校验函数。
- **默认值**：`packages/schema/src/resume/default.ts` 提供 `defaultResumeData`，新简历以此初始化。
- **持久化**：
  - `resume` 表存储当前简历（`data` 为 JSONB，含 `slug`/`tags`/`isPublic`/`isLocked`/`password`/`stylesheetRevision`/`renderDataVersion`）；
  - `resume_version` 记录不可变快照（模板切换、导入、AI 编辑、手动保存时生成），支撑撤销/回滚与历史对比；
  - `resume_statistics` + `resume_statistics_daily` 记录访问/下载统计；
  - `resume_analysis` 缓存 AI 分析结果。
- **校验链路**：前端 oRPC 输入 → API DTO（`packages/api/src/dto/resume.ts`）→ 领域层 `parseResumeData` → DB JSONB。

**关联代码资源：**
- 模型：`packages/schema/src/resume/{data.ts,default.ts,analysis.ts}`
- 表定义：`packages/db/src/schema/resume.ts`
- DTO：`packages/api/src/dto/resume.ts`
- 数据校验/预检：`packages/api/src/features/resume/resume-data-validation.ts`、`stylesheet-preflight.ts`、`stylesheet-preservation.ts`

### 3.5 AI 简历助手（Agent）

**核心实现思路：**
- **提供商抽象**：`packages/ai/src/types.ts` 定义 `AIProvider` 类型与 `aiProviderSchema`；`packages/api/src/features/ai/service.ts` 的 `getModel`/`getAgentModel` 依据 provider 类型工厂化创建模型（支持 OpenAI、Anthropic、Gemini、DeepSeek、Groq、Mistral、Ollama、Cerebras、Cohere、Fireworks、Perplexity、TogetherAI、XAI 等十余家，均通过 `@ai-sdk/*`）。
- **工具契约**：`packages/ai/src/tools/patch-proposal.ts` 定义 `resumePatchProposalToolInputSchema` / `OutputSchema`，AI 通过工具返回 JSON Patch 操作集（含步骤说明），`packages/api/src/features/agent/service.ts` 用 `normalizeAgentResumePatchOperations` 规整后经 `applyResumePatches` 应用到简历。
- **Agent 对话循环**：`packages/api/src/features/agent/service.ts` 基于 AI SDK 的 `ToolLoopAgent` + `streamText`，最多 30 步工具循环，支持图片/PDF/音频/文本附件（每种有大小与数量上限），服务端流式返回（`streamToEventIterator`）。
- **冲突处理**：Agent 写入前检查简历是否被外部修改，冲突则回滚（`ROLLBACK_CONFLICT_MESSAGE`），并提供运行取消（`AbortController` 管理活跃 run）。
- **配额与计费**：每次 AI 调用通过 `consumeThreadMessageQuota` 消耗线程配额，按 token 用 `deductBalanceByTokens` 扣除用户余额。
- **提示词体系**：`packages/ai/src/prompts/` 提供 `chatSystemPromptTemplate`、`analyzeResumeSystemPrompt`、PDF/DOCX 解析提示词；`packages/ai/src/resume/` 含 JSON 提取模板与结果清洗（`sanitizeAndParseResumeJson`）。

**关联代码资源：**
- 前端聊天页：`apps/web/src/routes/agent/`（13 个文件）
- 服务端 agent feature：`packages/api/src/features/agent/`（15 个文件，含 `service.ts`、`tools.ts`、`runs.ts`、`streams.ts`、`resume.ts`）
- AI 领域包：`packages/ai/src/{types.ts,prompts.ts,resume/,tools/}`
- 用户自配 provider：`packages/api/src/features/ai-providers/{router.ts,service.ts}`
- 计费/配额：`packages/api/src/features/{billing,quota}/service.ts`
- 文档：`docs/agent-chat.md`

### 3.6 认证与用户体系

**核心实现思路：**
- 基于 **Better Auth**（`packages/auth/src/config.ts`）统一配置：
  - 基础登录：邮箱+密码（bcrypt 哈希）、用户名；
  - 进阶：Passkey 插件、2FA 插件、Admin 插件、JWT/API Key 插件；
  - OAuth：Google / GitHub / LinkedIn 等预设 provider + 自定义 Generic OAuth（Discovery 或手动端点），并对 `OAUTH_AUDIENCES`（含 `/mcp`）做鉴权；
  - 邮箱验证/重置通过 `packages/email/templates/auth` 模板 + `sendEmail` 发送。
- **扩展字段**：通过 Better Auth `additionalFields` 挂接业务字段（billing、quota 等）。
- **限流**：生产环境启用 Better Auth 限流与 API 限流（`TRUSTED_IP_HEADERS`）。
- **HTTP 适配**：`apps/server/src/http/auth.ts` 将 Better Auth handler 挂到 `/api/auth`，并提供 OAuth token 验证（`verifyOAuthToken`）。

**关联代码资源：**
- 认证配置：`packages/auth/src/config.ts`
- OAuth 映射：`packages/auth/src/oauth-profile.ts`、`trusted-origins.ts`
- 用户表：`packages/db/src/schema/auth.ts`
- 前端认证路由/流程：`apps/web/src/routes/auth/`、`apps/web/src/features/auth/`

### 3.7 计费、配额与支付

**核心实现思路：**
- **配额**（`packages/api/src/features/quota/`）：按用户/套餐统计 AI 线程消息、附件等使用量，调用前检查余额与额度。
- **计费**（`packages/api/src/features/billing/`）：维护用户余额，AI 按 token 消耗实时扣减（`deductBalanceByTokens`）。
- **支付**（`packages/api/src/features/payment/`）：接入支付回调/订阅管理（配合 `billing` 联动）。
- 相关表与字段在 `packages/db/src/schema/auth.ts`（user 扩展字段）与支付相关表。

**关联代码资源：**
- `packages/api/src/features/{quota,billing,payment}/`
- 前端计费页：`apps/web/src/features/billing/`

### 3.12 API 层与 RPC 架构

**核心实现思路：**
- **oRPC**：`packages/api/src/context.ts` 定义请求上下文（`ctx`）与 `protectedProcedure`/`publicProcedure`，统一注入认证、限流、国际化等中间件。
- **功能路由**：`packages/api/src/features/*` 每个目录为一个 feature（admin、agent、ai、ai-providers、auth、billing、feedback、flags、payment、quota、resume、storage），目录内为 `router.ts`（过程定义 + 路由元信息 + 错误映射）、`service.ts`（业务实现）、`inputs.ts`/`dto`（Zod 输入输出）。
- **聚合**：`packages/api/src/routers/` 聚合所有 feature router，通过 `apps/server/src/rpc/` 挂载到 `/api/rpc`。
- **前端调用**：`apps/web/src/libs/orpc/client.ts` 提供同构客户端——服务端走内存 router，浏览器走 `/api/rpc`（带 credentials）。
- **OpenAPI**：过程自带 `.route()` 元数据（method/path/tags/operationId/description），`apps/server/src/openapi/` 据此生成 OpenAPI 文档。
- **限流**：`packages/api/src/middleware/rate-limit.ts` 提供 `resumeMutationRateLimit` 等写操作限流。

**关联代码资源：**
- `packages/api/src/context.ts`、`packages/api/src/routers/`
- `packages/api/src/features/*`、`packages/api/src/dto/*`、`packages/api/src/middleware/`
- `apps/server/src/{http,rpc,mcp,openapi,static,startup}`
- 前端客户端：`apps/web/src/libs/orpc/client.ts`

| `src/index.ts` | 组装 Hono app、启动迁移、挂载全部路由、静态产物回退 |
| `src/http/` | HTTP 路由：`auth.ts`（认证）、`uploads.ts`、`page.ts`、`resume.ts` 等 |
| `src/rpc/` | 挂载 oRPC router 到 `/api/rpc` |
| `src/mcp/` | MCP 服务入口 |
| `src/openapi/` | 从 oRPC 路由元数据生成 OpenAPI |
| `src/static/` | 静态资源（上传文件、web 构建产物） |
| `src/startup/` | 启动检查（数据库连接、迁移等） |

## 6. 数据库 Schema 概览

| 表 | 用途 |
|---|---|
| `user`（`auth.ts`） | 用户 + Better Auth 扩展字段（配额/计费等） |
| `resume` | 简历主表（JSONB 数据、slug、公开/锁定、样式版本） |
| `resume_version` | 简历不可变快照（撤销/回滚/对比） |
| `resume_statistics` / `resume_statistics_daily` | 访问/下载统计 |
| `resume_analysis` | AI 分析结果缓存 |
| Agent 相关表 | 线程（`agent_thread`）、消息（`agent_message`）、动作（`agent_action`）、附件（`agent_attachment`） |
| AI Provider 相关表 | 用户可配置的 AI 提供商凭证 |
| 计费/支付相关表 | 订阅、余额、订单 |

> 完整表定义见 `packages/db/src/schema/*.ts`；迁移 SQL 在根目录 `migrations/`。新增表后用 `dotenvx run -f .env.local -- pnpm db:generate` 生成迁移。

## 7. 常见开发命令速查

| 命令 | 说明 |
|---|---|
| `pnpm install` | 安装依赖 |
| `pnpm dev`（`dotenvx run -f .env.local --`） | 启动开发服务（端口 3000） |

> 关键约束：workspace 内依赖必须通过包名（如 `@reactive-resume/ui`）引用，禁止相对路径穿透源码；新增环境变量必须同步加入 `turbo.json` 的 `globalEnv`；`routeTree.gen.ts` 为自动生成文件，禁止手改。
