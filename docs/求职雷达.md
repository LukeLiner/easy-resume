# 求职雷达（JD 匹配优化）需求文档

## 1. 背景与目标

用户在编辑简历时，往往不清楚目标岗位需要什么、自己的简历差距在哪。**求职雷达**是一个新 Tab 页，让用户粘贴目标岗位 JD（Job Description），由 AI 解析 JD 关键要求并结合用户当前简历，输出**定制化修改建议**和**优化后的简历草稿**，帮助用户生成高匹配度简历。

## 2. 功能需求

### 2.1 岗位信息输入（粘贴文本）

- 在「求职雷达」Tab 提供多行文本输入区，支持粘贴 JD 原文。
- 输入校验：非空、长度上限（如 20,000 字符），超出提示。
- 保留历史分析记录入口（后续版本可支持按简历/岗位归档）。

### 2.2 AI 解析 JD 关键要求

粘贴 JD 后触发 AI 解析，结构化提取：

| 解析维度 | 输出示例 |
| --- | --- |
| 硬性技能 | `React / TypeScript / Node.js` |
| 经验要求 | `3 年以上前端开发经验`、`有大流量系统经验` |
| 软素质 | `跨团队沟通`、`自驱力`、`owner 意识` |
| 加分项 | `有 AI 产品经验优先` |

### 2.3 匹配分析（结合当前简历）

基于 JD 解析结果与用户简历，输出六维分析：

| 分析维度 | 输出内容 |
| --- | --- |
| 关键词匹配度 | 简历中出现的 JD 核心关键词覆盖率（如 12/20），缺失项高亮列出 |
| 经验/技能差距 | 识别 JD 要求但简历未体现的能力，给出补充建议（如「建议添加 XX 项目经验」） |
| 表达优化 | 建议将经历改用更贴合 JD 的动词/术语（如「负责」→「主导/推动」） |
| 量化建议 | 提示把模糊描述（「业绩良好」）改为量化成果（「提升转化率 15%」） |
| 排序调整 | 建议优先展示与 JD 最相关的经历模块 |
| 格式/结构建议 | 调整结构以符合行业惯例（技术岗突出项目、销售岗突出业绩） |

### 2.4 优化简历草稿

- 基于上述分析，生成一份**优化后的简历草稿**（不直接覆盖用户简历）。
- 草稿以「建议 + 示例改写」形式逐条展示，用户可选择采纳/忽略。
- 采纳方式（参考现有 Agent 链路）：走 `apply_resume_patch` 以 JSON Patch 方式应用到当前简历，保留快照可回滚。

## 3. 交互流程

```
进入「求职雷达」Tab
   │
   ▼
粘贴 JD → 点击「开始解析」
   │
   ▼
AI 解析 JD（技能/经验/软素质/加分项）＋ 六维匹配分析
   │
   ├─ 关键词覆盖率 + 缺失项高亮
   ├─ 差距清单 + 补充建议
   ├─ 表达/量化/排序/结构建议
   └─ 优化草稿（逐条 采纳/忽略）
   │
   ▼
采纳项批量应用 → 生成高匹配度简历（可回滚）
```

## 4. 技术方案要点

- **入口**：`apps/web/src/routes/builder/$resumeId/-components/combined-sidebar.tsx` 新增 `BuilderSidebarTab = "job-radar"`，TabsList 由 3 列扩为 4 列。
- **页面组件**：`apps/web/src/routes/builder/$resumeId/-sidebar/right/sections/job-radar/`（懒加载，结构对齐 `resume-analysis`）。
- **后端**：`packages/api/src/features/agent/` 新增 `job-radar` 相关 RPC（`protectedProcedure` + AI 限流）：
  - `parseJd({ resumeId, jdText })` → 解析结果 + 六维分析；
  - 应用采纳项复用既有 `apply_resume_patch` / `agent_action` 链路，支持回滚。
- **提示词**：构造 agent 指令约束「先 `read_resume` 读取简历，再输出分析，如需改动用 `apply_resume_patch`」，保持简历原有语言/语气/结构。
- **数据模型**：JD 文本与解析结果可落库（`resume_id`、`jd_text`、`parsed_json`、`created_at`），便于历史记录与二次分析。
- **i18n**：所有文案走 `t` macro（`@lingui/core/macro`）。
